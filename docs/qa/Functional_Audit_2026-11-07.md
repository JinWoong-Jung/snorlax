# 잠만보 기능 구현 점검 보고서

> 이 문서는 후속 수정 전 기록입니다. 최신 구현과 검증은 [기능 구현 보고서](Functional_Implementation_2026-11-07.md)를 확인하세요.

점검일 2026-11-07. 대상은 현재 작업 디렉터리의 Jammanbo.xcodeproj와 Swift 소스다. GitHub에 아직 반영되지 않은 작업도 포함한다. 애플리케이션 코드를 수정하지 않고 검토했다.

## 판정과 검수 범위

캘린더 외부 연동과 생성형 LLM 요약은 이번 검수에서 제외한다. 그 외 수면 수집·표시, 체크인, 추세, 기록 기반 질문, 수면 목표, 수동 일정과 비생성형 요약 PDF를 확인했다.

**핵심 기능은 구현되어 있으나 전체가 온전히 완료된 상태는 아니다.** 특히 수면 집계에 재현 가능한 오류가 있어 실제 수면 시간, 단계, 최근 평균, 생활습관 비교와 PDF 수치가 영향을 받을 수 있다. Watch 전달은 기본 전송 경로가 있지만 오류 후 복구와 실기기 검증이 남아 있다.

최근 SSRD의 제외 범위에는 서버 계정·클라우드와 자동 일정 최적화도 들어 있다. 따라서 ‘캘린더와 LLM만 제외’라는 문장만으로 그 기능까지 완료했다고 판단하지 않는다. 현재 SSAD가 구체적으로 정의한 여섯 프로세스를 본 보고서의 기능 기준으로 사용한다. 계정, 클라우드 백업, 알림, 수면·체크인 수정 및 삭제, 자동 주간 최적화는 현 앱에 구현되어 있지 않다.

## 우선 수정할 문제

### FA01 높은 우선순위 자정을 넘긴 수면이 두 날짜로 분리됨

위치: `Jammanbo/Health/SleepStore.swift:81`부터. 각 단계 샘플을 종료 날짜의 startOfDay로 그룹화한다. 한 번의 수면 세션에 속하는 단계들이 자정 전후에 끝나면 서로 다른 밤으로 나뉜다. 홈은 이를 기상 기준의 어젯밤 수면으로 표시하므로 날짜별 값이 잘못된다.

재현 입력은 11월 6일 22:30~23:30의 60분과 같은 날 23:30~11월 7일 06:30의 420분이다. 기대 결과는 11월 7일 기상 기준 480분이다. 실제 결과는 11월 6일 60분, 11월 7일 420분이다.

수정 방향: 구간을 수면 세션 또는 명확한 수면 일자 경계로 묶고, 전체 수면을 기상일에 대응시킨다. 사용한 날짜 경계를 UI·비교·PDF에서 공유한다. 낮잠·교대 근무를 포함한 정책도 명시한다.

### FA02 높은 우선순위 겹치는 수면 구간이 이중 합산됨

위치: `Jammanbo/Health/SleepStore.swift:93`부터. 샘플의 출처·겹침을 판단하지 않고 각 지속 시간을 합산한다.

재현 입력은 같은 날 00:00~08:00 구간의 core 기록과 동일 시간의 unspecified 기록이다. 실제 시간이 한 번의 480분 구간이라면 고유 지속 시간은 480분이어야 한다. 현재 결과는 960분이다. 다른 수면 앱이나 원본이 중복된 경우의 처리 규칙이 없다.

수정 방향: 출처 우선순위와 겹친 시간 구간의 병합·상세 단계 우선 규칙을 정의하고 총 시간이 같은 실제 구간을 중복 세지 않도록 한다. inBed를 제외하는 현재 처리만으로 겹치는 asleep 기록의 중복이 해결되지는 않는다.

추가 확인: 지속 시간을 샘플별로 정수 분으로 버린 뒤 합치므로 1분보다 짧은 구간은 누락된다. 분 표시 전 초 단위 누적 여부도 정규화 수정에 함께 포함한다.

### FA03 중간 우선순위 지연 도착한 Watch 기록이 최신 기록을 밀어냄

위치: `Jammanbo/CheckIn/CheckInStore.swift:38`부터, 표시 위치 `Jammanbo/CheckInView.swift:92`.

현재 insert는 도착한 항목을 앞에 넣은 뒤 앞의 30건을 보관한다. 기록 시각으로 정렬하지 않는다. 최근 기록 30건이 있는 상태에서 10일 전 Watch 기록이 뒤늦게 도착하면 이 오래된 기록이 첫 줄에 나타나고 최근 기록 한 건이 보관 대상에서 빠진다. 재현에서 최근 30건 중 29건만 남았다.

수정 방향: UUID 중복 제거 후 기록 시각 기준으로 정렬하고 최근 보관 한도를 적용한다. 수신 시각과 사용자가 기록한 시각을 구분한다.

### FA04 중간 우선순위 Watch 전송 실패 복구 미구현

위치: `JammanboWatch/Connectivity/WatchSessionStore.swift:68`부터.

transferUserInfo 호출 뒤 앱 대기열을 즉시 지운다. 시스템은 자체 전송 큐를 유지하므로 이 동작만으로 정상 전송이 곧바로 유실된다고 판단하지 않는다. 다만 session(_:didFinish:error:) 구현과 실패 시 재저장이 없어 실제 전송 오류를 감지하거나 앱에서 복구할 경로가 없다. Watch 화면도 수신 완료 확인을 받지 않는다.

수정 방향: 전송 ID와 완료·실패 콜백을 관리하고 실패한 항목을 안전하게 재시도한다. 정상적인 일시 비연결은 시스템 큐를 활용하며 도착 여부는 iPhone 기록과 구분해 표시한다. 반드시 페어링된 실기기에서 시험한다.

### FA05 중간 우선순위 저장된 기록의 전체 조회 경로 부족

위치: `Jammanbo/CheckInView.swift:92`, `Jammanbo/SummaryView.swift:43`.

체크인은 앞의 4건만, 수면 요약은 앞의 5건만 표시한다. 다음 페이지, 전체 목록 또는 날짜별 상세 진입이 없다. 저장되어 있어도 사용자가 다른 항목을 찾아볼 수 없다. 특히 체크인을 여러 번 저장하면 며칠 전 기록을 쉽게 확인할 수 없다.

수정 방향: 전체 체크인 목록과 최근 7일 수면 목록, 날짜별 상세를 제공한다. 입력 수정·삭제가 이번 범위에 포함되는지도 요구사항에서 명시하고 구현을 맞춘다.

### FA06 중간 우선순위 화면 갱신 후 이전 PDF가 계속 공유될 수 있음

위치: `Jammanbo/SummaryView.swift:6`, `:66`, `:108`.

shareURL은 PDF를 생성할 때만 바뀐다. 생성 뒤 다른 탭에서 체크인을 추가하거나 건강 기록을 갱신해도 기존 URL을 해제하지 않는다. 요약 화면에는 새 개수가 보이지만 공유 버튼은 이전 PDF를 계속 가리킬 수 있다.

재현 절차: 체크인 1건일 때 PDF 생성 → 체크인 탭에서 1건 추가 → 요약의 2건 표시 확인 → 기존 PDF 공유 버튼 선택. 다시 생성하기 전에는 PDF의 체크인 수가 1건으로 남는 구조다. 이는 코드 상태 흐름으로 확인했으며 실제 공유 시트 조작은 실행하지 않았다.

수정 방향: 요약 입력 변경 시 기존 PDF를 무효화하거나 공유 시 새로 생성한다. 앱 안에서 내용과 생성 시각을 확인할 PDF 미리보기도 추가한다.

### FA07 자동 갱신과 지속 사용 확인 미완료

위치: `Jammanbo/JammanboApp.swift:5`, `Jammanbo/Health/SleepStore.swift:6`, `Jammanbo/SleepDashboardView.swift:181`.

앱은 시작 시 샘플 목록을 만들고 건강 연결 버튼을 눌러야 실제 기록을 조회한다. 자동 조회·HealthKit 변경 관찰·앱 복귀 시 갱신이 없다. 앱을 다시 열 때도 샘플부터 표시한다. 매일 새 수면이 자동 반영되는 경험을 요구한다면 현재는 미구현이다.

수정 방향: 권한 요청 시점과 이후 조회 시점을 구분하고, 앱 진입·복귀 시점과 HealthKit 변경에 맞춘 갱신 정책을 추가한다. 실제 권한 상태는 읽기 거부 여부를 단정하지 않고 처리한다.

## 완료 기준과 다음 작업 순서

1. 수면 세션 날짜·겹침·초 단위 집계를 먼저 수정하고 재현 입력을 회귀 검사로 추가한다.
2. 체크인 기록 시각 정렬과 전체 이력 조회를 구현한다.
3. Watch 전송 오류·재시도와 실기기 전달을 확인한다.
4. PDF 갱신·미리보기, 앱 복귀 시 건강 기록 갱신을 구현한다.
5. 실제 iPhone에서 권한·저장·재실행·키보드·PDF 공유 취소를 확인하고 Watch 선택 과업도 실기기에서 수행한다.

이 작업들은 캘린더 외부 연동이나 생성형 LLM 없이 구현할 수 있다. 고객 테스트 전에는 위의 수면 수치 오류를 우선 해결해야 한다. 기능 존재 여부에 임의의 완료율을 붙이지 않는다.

## API 확인 근거

- [Apple HealthKit 수면 단계와 샘플 구간](https://developer.apple.com/documentation/healthkit/hkcategoryvaluesleepanalysis): 단계별 샘플과 구간을 설명한다. 앱이 표시할 수면 세션을 직접 정규화해야 한다는 검토의 배경이다.
- [Apple WatchConnectivity 전송 완료와 오류 콜백](https://developer.apple.com/documentation/watchconnectivity/wcsessiondelegate/session(_:didfinish:error:)-8627b): 전송 완료 또는 실패를 알리고 오류에 대응하는 경로를 제공한다.
- [Apple transferUserInfo 문서](https://developer.apple.com/documentation/watchconnectivity/wcsession/transferuserinfo(_:)): 시스템 큐 전송이며 시뮬레이터 대신 페어링 기기에서 시험하도록 안내한다.
