2026-11-07. 대상은 현재 작업 디렉터리의 iPhone·Apple Watch 앱이다. 외부 캘린더 연동과 생성형 LLM 요약은 제외했다. 기존 목표·수동 일정·규칙 기반 질문과 비생성형 요약은 유지한다.

실제 HealthKit 원본 수면은 읽기 전용이다. 앱에서 수정·삭제할 수 있는 기록은 체크인이다. 체크인 수정은 UUID·원래 시각·출처를 유지한다.

## 데이터 규칙

- 겹친 수면은 상세 단계, Watch 출처, 출처 식별자 순으로 선택한다. 같은 출처의 충돌에서는 awake를 우선한다. 상세 단계가 없는 수면은 미분류로 보관한다.
- 수면 간격 90분 이내이거나 하나의 inBed 구간으로 연결되면 같은 세션이다. 이는 앱의 분류 정책이며 교대 근무·분절 수면의 실제 자료로 추가 평가한다.
- iPhone 수신 UUID 이력은 최대 1,000개다. 이력이 남은 동안 Watch 재전송은 중복을 만들거나 폰에서 수정·삭제한 값을 복구하지 않는다. 표시·보관 대상은 기록 시각순 최근 30건이다.
- Watch 대기열은 확인 응답까지 최대 30건 유지한다. 가득 차면 새 입력을 거부하고 안내한다. 운송 중인 UUID는 중복 예약하지 않는다. 오류는 5초부터 최대 300초까지 간격을 늘리며 운송 성공 후 앱 확인이 없으면 60초 뒤 재시도한다. 운영체제의 백그라운드 실행·전달 시점은 즉시성을 보장하지 않는다.
- 건강 연결 요청 여부만 저장하고 수면 조회 결과는 메모리에 둔다. 빈 응답을 읽기 권한 거부라고 단정하지 않는다. 수면·출처·기간 변경은 질문·요약·PDF에 같은 기준으로 반영한다.
- 생성 시 앱 자체 임시 PDF 중 24시간 지난 파일을 정리한다. PDF는 사용자 선택으로만 외부 공유한다.

Mac Catalyst 검증 앱은 별도 번들 ID `com.team17.jammanbo.localpreview`와 별도 로컬 저장 영역을 사용했다. 실제 iPhone 앱의 데이터를 조작하지 않았다. 이 실행은 iPhone 소프트웨어 키보드·HealthKit·Watch 통합 검증을 대체하지 않는다. 공유 상대를 선택하거나 파일을 외부 전송하지 않았다. 삭제 기능은 저장소 회귀 검사로 확인했다.

빌드 명령:

```sh
xcodebuild -project Jammanbo.xcodeproj -scheme Jammanbo \
  -destination 'generic/platform=iOS' \
  -derivedDataPath /tmp/jammanbo-functional-fix/build \
  CODE_SIGNING_ALLOWED=NO build
```

로그는 작업 시점의 `/tmp/jammanbo-functional-fix-build.log`에 있다. 임시 파일은 영구 보관을 보장하지 않는다. 기기 서명 Team과 기존 저장 키를 유지했다.

SSRD·SSAD는 v1.3으로 갱신하고 UI/UX 루트 원본과 v5 사본, 고객 과업 양식, README도 동기화했다. 최종 SSRD 4페이지, SSAD 9페이지, 고객 양식 6페이지와 UI/UX 13슬라이드를 렌더링해 전 페이지의 한글·표·줄바꿈·빈 페이지 여부를 확인했다. 제출 PDF 3개도 같은 내용으로 다시 내보냈다. 제공받은 SSAD 참고 원본은 수정하지 않았다.

## 실제 iPhone·Watch에서 마칠 확인

현재 환경에는 사용 가능한 iOS·watchOS 시뮬레이터 런타임이 없다. 이번 작업에서 실제 기기 설치·조작은 수행하지 않았다. 코드 구현과 위 검사까지 완료했으며 아래는 실제 하드웨어 검수다.

1. Xcode에서 최신 `Jammanbo` 스킴을 본인 iPhone에 다시 실행한다. 앱 삭제 없이 업데이트하면 기존 체크인·목표·일정을 유지한다.
2. 건강 연결 후 실제 기록의 기상일·시간·단계와 Apple 건강 앱을 대조한다. 앱 재실행·복귀·새로고침 후 출처와 값도 확인한다.
3. 체크인 저장·전체 목록·수정·삭제, 재실행 보관을 확인한다. 질문·계획 입력 후 완료 버튼과 제출로 iPhone 키보드가 닫히는지 확인한다.
4. PDF 미리보기 후 체크인을 바꾸고 다시 생성한다. 새 내용과 출처를 확인하고 시스템 공유 시트는 전송 없이 취소한다.
5. Watch 체크인 1건 저장 후 폰 실제 도착·출처와 Watch의 마지막 저장 확인 시각을 확인한다. 연결을 끊고 입력한 뒤 재연결하여 대기 항목이 한 번만 반영되는지 확인한다. 실패하면 Watch 상태 문구와 Xcode 로그로 원인을 기록한다.

실제 고객 과업 결과·피드백 분석과 공개 시연 영상은 별도 수집·촬영해야 한다. 자동 검사와 개발자 화면 확인을 고객 테스트로 집계하지 않는다.
