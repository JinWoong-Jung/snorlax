## 1 문서 목적과 서비스 목표

본 명세서는 프로토타입이 현재 제공하는 기능, 사용자 인터페이스, 데이터 처리 경계와 품질 목표를 정의한다. 임상 진단이나 치료를 제공하지 않으며, 개인이 자신의 기록을 이해하고 상담에 참고할 요약을 준비하는 데 초점을 둔다.

HMW
어떻게 하면 사용자가 적은 노력으로 수면과 생활습관 기록을 이어가고, 기록을 바탕으로 현실적인 수면 목표를 세울 수 있을까?


## 2 범위와 가정

| 구분 | 프로토타입 요구사항 |
| --- | --- |
| 수면 데이터 | HealthKit의 sleepAnalysis를 사용자가 허용한 범위에서 읽는다. 권한 또는 기록이 없으면 샘플 자료를 표시하고 출처를 구분한다. |
| 체크인 | 기분, 스트레스, 오후 카페인을 iPhone 또는 Watch에서 입력한다. Watch 기록은 페어링된 iPhone으로 전달한다. |
| 질문과 계획 | 질문은 기기 내 규칙으로 답한다. 목표 수면시간과 기상 시각으로 취침 목표를 계산하며 일정을 수동 입력한다. |
| 저장과 공유 | 체크인·목표·일정은 기기에 저장한다. 최근 7일 요약 PDF는 사용자가 생성하고 공유 대상을 선택한다. |
| 제외 범위 | 캘린더 계정 동기화, 서버 계정·저장소, 생성형 LLM, 자동 일정 최적화는 포함하지 않는다. |


## 3 사용자와 외부 시스템

| 주체 | 필요 또는 책임 |
| --- | --- |
| 사용자 | HealthKit 권한 선택, 체크인·목표·일정 입력, 질문, PDF 공유 여부 결정 |
| Apple HealthKit | 허용된 수면 분석 데이터를 iPhone 앱에 읽기 제공 |

4 기능 요구사항 수면 체크인 질문

각 요구사항은 프로토타입의 관찰 가능한 동작을 정의한다. 우선순위는 제출용 시제품에서 검증할 중요도를 나타낸다.

| ID / 우선순위 | 기능 요구사항 | 인수 기준 |
| --- | --- | --- |
| FR-01 매우 높음 | 최근 7일 수면의 날짜, 총 시간과 제공된 단계를 표시한다. 미분류 수면과 단계 미제공을 구분하고 샘플 출처를 표시한다. | 기록이 있으면 대시보드와 요약에 출처가 표시된다. 기록이 없으면 샘플 경로임을 알 수 있다. |
| FR-02 높음 | 사용자 권한을 받은 뒤 HealthKit sleepAnalysis를 읽는다. 수면 자료는 서버로 전송하지 않는다. | 연결 후 실행·복귀·변경 시 재조회한다. 수면은 겹침을 제거하고 기상일로 집계하며 빈 결과는 샘플 출처를 표시한다. |
| FR-03 매우 높음 | 기분, 스트레스, 오후 카페인 여부를 iPhone 또는 Watch에서 기록한다. | Watch는 iPhone 저장 확인까지 큐를 유지하고 실패 시 재시도한다. 기록 시각순 보관과 UUID 중복 방지를 확인한다. |
| FR-04 높음 | 최근 7일 수면 상세와 체크인 전체 이력을 조회한다. 체크인은 수정·삭제하며 건강 원본은 읽기 전용이다. | 수면 7일과 체크인 최근 30건을 조회하고, 체크인 수정·삭제 결과가 재실행 후 유지된다. |
| FR-05 높음 | 로컬 규칙으로 평균 수면, 수면 단계, 같은 날짜의 생활습관 비교 질문에 답한다. | 대표 질문에 해당하는 계산 결과 또는 데이터 부족 안내를 제공한다. |
| FR-06 매우 높음 | 답변에 계산에 사용한 날짜·출처를 함께 표시한다. | 답변에 날짜·출처가 보이며 비교에서는 각 조건의 기록 수와 자료 부족 상태를 확인한다. |


해석 기준
비교 결과는 관찰된 기록의 단순 평균이다. 생활습관이 수면 변화를 일으켰다고 해석하거나 의료적 판단을 제시하지 않는다.



5 기능 요구사항 계획 요약

| ID / 우선순위 | 기능 요구사항 | 인수 기준 |
| --- | --- | --- |
| FR-07 높음 | 같은 날짜의 실제 수면과 하루 최신 체크인을 결합해 카페인 또는 스트레스 조건별 평균을 비교한다. | 조건별로 최소 2일의 실제 수면·체크인 결합 기록이 필요하다. 샘플 수면과 개인 체크인은 비교하지 않는다. |
| FR-08 높음 | 사용자가 일정 제목, 날짜, 시간을 직접 입력하고 기기에 저장한다. | 추가한 일정이 목록에 나타나고 다시 열어도 유지된다. |
| FR-09 매우 높음 | 목표 수면 360~600분과 기상 시각으로 취침 목표를 계산한다. 수동 일정은 계산에 자동 반영하지 않는다. | 8시간 수면과 07:00 기상 설정은 23:00 취침 목표를 제안한다. |
| FR-10 높음 | 사용자가 목표 수면시간과 기상 시각을 수정한다. | 변경한 목표가 이후 앱 실행에도 유지된다. |
| FR-11 높음 | 최근 7일 수면과 체크인 개수를 요약해서 보여준다. | 요약 화면에서 기간, 평균, 기록 출처와 일별 자료를 확인할 수 있다. |
| FR-12 보통 | 요약을 1페이지 PDF로 만들고 시스템 공유 화면을 연다. | 앱 내부 PDF 미리보기에서 기간·출처를 확인한다. 기록 변경 시 무효화하고 공유 시 최신 PDF를 생성한다. |


## 6 비기능 요구사항

| ID | 품질 요구사항 | 상태 |
| --- | --- | --- |
| NFR-01 | Watch 체크인은 사용성 목표 60초 이내 완료를 지향한다. 실제 소요시간은 고객 테스트에서 측정한다. | 검증 전 |
| NFR-02 | 로컬 화면 전환과 규칙 계산은 체감상 즉시 응답해야 한다. 목표 기준은 1초 이내다. | 기기 측정 전 |
| NFR-03 | 질의 답변은 날짜·출처 근거 또는 데이터 부족 안내를 포함한다. | 구현됨 |
| NFR-04 | HealthKit 수면 데이터는 읽기 전용이며 서버로 전송하지 않는다. PDF 공유는 사용자 동작으로 시작한다. | 구현됨 |
| NFR-05 | 색상만으로 상태를 구분하지 않고 읽기 쉬운 텍스트와 대비를 사용한다. | 시각 검토 필요 |
| NFR-06 | HealthKit 권한 거부·기록 부재 상태에서도 샘플 또는 안내 화면을 제공한다. | 구현됨 |
| NFR-07 | 향후 캘린더, LLM, 클라우드 저장을 추가할 때 별도 동의와 데이터 보호 설계를 적용한다. | 후속 기준 |



7 인터페이스와 데이터 규칙

| 영역 | 현재 인터페이스 | 데이터 규칙 |
| --- | --- | --- |
| 수면 | iPhone HealthKit sleepAnalysis 읽기 | 사용자가 HealthKit 접근을 허용한다. 앱은 수면 기록을 수정하지 않는다. |
| Watch 체크인 | watchOS SwiftUI + WatchConnectivity userInfo 전달 | 기분·스트레스·카페인 선택값을 페어링된 iPhone으로 보낸다. |
| 질문 | iPhone 로컬 규칙 | 최근 7일 범위에서 계산하고 근거 날짜와 출처를 표시한다. |
| 계획 | 목표 시각 계산 + 수동 일정 입력 | 목표 수면시간을 기상 목표에서 빼 취침 목표를 구한다. 일정은 캘린더와 동기화하지 않는다. |
| 요약 PDF | UIKit PDF 렌더링 + iOS 공유 시트 | 최근 수면·체크인 요약을 임시 PDF로 만들며 사용자 선택 후 공유한다. |
| 저장 | UserDefaults 및 기기 로컬 상태 | 체크인 최근 30건과 목표·일정은 UserDefaults에 저장한다. 수면 조회 결과는 메모리에 보관한다. |


## 8 데이터 부족과 복구 동작

| 상황 | 요구되는 동작 |
| --- | --- |
| HealthKit 권한 거부 또는 데이터 없음 | 사용자가 상태를 이해할 수 있도록 설명하고 샘플 데이터에는 샘플 출처를 명시한다. |
| 카페인·스트레스 비교 표본 부족 | 비교 수치 대신 필요한 체크인 기록이 부족하다고 안내한다. |
| Watch 연결 지연 | 체크인은 WatchConnectivity 대기열에 남고 연결 가능한 시점에 iPhone으로 전달된다. |
| PDF 생성·공유 취소 | 원본 기록은 유지하고 공유 여부를 사용자에게 맡긴다. |


## 9 수용 검증 시나리오

| 시나리오 | 통과 조건 |
| --- | --- |
| HealthKit과 샘플 기록 | 권한과 기록 상태에 맞는 데이터가 표시되고 샘플 출처가 숨겨지지 않는다. |
| Watch 체크인 전달 | Watch에서 저장한 항목이 페어링 iPhone에 도착하고 입력값을 확인할 수 있다. |
| 기록 질의 | 최근 평균 수면 질문에 계산 범위·출처를 확인하고, 비교 자료 부족 시 그 상태를 확인한다. |
| 목표 취침 계산 | 8시간·07:00 설정이 23:00 취침 목표로 계산되고 변경한 값이 유지된다. |
| 요약 PDF | 최근 7일 요약을 1페이지 PDF로 만들어 공유 화면을 열 수 있다. |


검증 상태
서명 없는 iPhone·Watch 빌드와 계산·저장 경계 검사를 수행한다. iPhone 실행은 사용자 보고로 확인했고 실제 HealthKit·Watch 전달·고객 과업은 별도 검증한다.
