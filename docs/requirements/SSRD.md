# 잠만보 요구사항 명세서

SSRD · iPhone + Apple Watch 동반 앱

버전 v1.5 · 2026-11-08 · Team 17

## 1 문서 목적과 서비스 목표

HealthKit 수면과 생활습관을 함께 돌아보고, 기록에 근거한 질문·현실적인 취침 제안·사용자가 선택한 상담용 PDF를 제공한다. 임상 진단이나 치료를 제공하지 않는다. P03·P05 개선 요구를 유지하고, 이번 개정에서는 외부 API를 이용한 LLM 질문·설명 및 상담용 요약 초안을 설계 범위에 추가한다. API 연동은 설계 가정이며 현재 앱의 구현·검증 결과와 구분한다.

어떻게 하면 사용자가 적은 노력으로 수면과 생활습관을 기록하고, 계산 근거를 이해하며, 자신의 데이터를 직접 통제할 수 있을까?

## 2 범위와 가정

| 구분 | 프로토타입 요구사항 |
|---|---|
| 실행 환경 | iOS 17 이상 iPhone 앱, watchOS 10 이상 동반 앱. 첫 검증은 iPhone 중심이며 Watch 전달은 별도 실기기 검증한다. |
| 수면 데이터 | HealthKit sleepAnalysis 읽기 전용. 읽을 수 있는 기록이 없으면 샘플과 출처를 명시한다. |
| 체크인·질문 | 기분·스트레스·오후 카페인·운동 여부를 기록한다. 기기 내 규칙으로 평균·단계·같은 날짜의 습관별 비교에 답한다. |
| 계획 | 기상 날짜·시각과 수면 목표, 수동 일정의 시작·종료를 이용해 해당 밤의 취침 제안을 계산한다. |
| 저장·공유 | 체크인·목표·일정은 로컬 저장. 최근 7일 중 날짜·필드 선택, PDF 확인과 최종 동의 후 시스템 공유 시트를 연다. |
| LLM API 설계 가정 | 선택 기록·질문을 중계 서버를 통해 LLM API에 보내 설명과 요약 초안을 받는다. 11절 FR-13~16은 추가 설계이며 실제 호출·구현 검증 전이다. |
| 제외 범위 | 외부 캘린더 동기화, 서버 계정·클라우드 보관, 주간 최적화·자동 전송. LLM의 진단·치료 판단과 근거 없는 수치 생성도 제외한다. |

## 3 사용자와 외부 시스템

| 주체 | 필요 또는 책임 |
|---|---|
| 사용자 | 건강 접근 요청, 체크인·질문·목표·일정 입력, 공유 데이터 선택·PDF 확인·최종 동의와 수신자 결정. |

| 상담자·공유 대상 | 앱 계정이나 직접 전송 API 없이, 사용자가 외부 공유를 완료한 경우에만 선택된 PDF를 받는다. |

## 4 기능 요구사항: 기록과 질문

| ID / 우선순위 | 기능 요구사항 | 인수 기준 |
|---|---|---|
| FR-01 매우 높음 | 최근 7일 수면·단계·출처를 표시한다. | 단계 미제공과 0분을 구분하고 샘플 표시를 유지한다. |
| FR-02 높음 | 사용자 요청 후 HealthKit을 읽고 실행·복귀·변경 시 갱신한다. | 겹침 제거 후 기상일로 합산한다. 빈 결과·조회 실패는 안내와 샘플 출처를 표시한다. |
| FR-03 매우 높음 | 폰·Watch에서 기분·스트레스·오후 카페인·운동을 저장한다. | 운동은 있음·없음·미기록을 구분한다. 구형 기록은 미기록으로 유지한다. Watch는 UUID 중복 없이 폰 확인까지 재시도한다. |
| FR-04 높음 | 수면 상세와 체크인 이력을 조회·편집한다. | 수면 최근 7일, 체크인 최근 30건을 조회한다. 체크인 수정·삭제·운동 값은 재실행 후 유지된다. 건강 원본은 읽기 전용이다. |
| FR-05 높음 | 규칙 기반 질문에서 지원 범위의 표현 변형을 인식한다. | ‘운동한 날 수면이 달랐나?’, 산책·러닝·workout, 커피·긴장 표현을 해당 비교로 분류한다. 여러 습관을 묻는 경우 하나를 선택하도록 안내한다. |
| FR-06 매우 높음 | 답변과 ‘비교 기준’에 계산 근거와 한계를 표시한다. | 두 평균·차이·각 일수·날짜·출처와 제외 기준을 확인한다. 조건별 2일은 계산 최소치이며 통계적 유의성·인과관계·의학적 효과가 아님을 설명한다. |
| FR-07 높음 | 같은 기상 날짜의 실제 수면과 하루 최신 체크인으로 습관별 평균을 비교한다. | 운동 있음/없음, 카페인 있음/없음, 높은 스트레스/나머지 각 2일 이상일 때만 계산한다. 운동 미기록은 제외하고 샘플 수면은 비교하지 않는다. |

운동의 산책·러닝 등 표현은 운동 여부로 묶는다. 운동 종류·강도별 분석은 제공하지 않는다. 지원하지 않는 질문에는 범위와 예시를 안내한다. ‘의미 있는 변화’를 판단하는 임계값이나 통계 검정은 구현 범위에 없다.

## 8 부족·오류·취소와 복구

| 상황 | 요구되는 동작 |
|---|---|
| 수면 없음·오류 | 상태와 샘플 출처를 표시한다. 빈 응답만으로 권한 거부를 단정하지 않는다. |
| 비교 각 그룹 2일 미만 | 수치 대신 그룹별 일수·날짜와 추가 기록 안내. 운동 미기록과 샘플은 비교에서 제외한다. |
| 일정이 기상 이후까지 지속 | 확보 수면 0으로 제한하고 일정·기상 조정을 안내한다. 여러 충돌은 가장 늦은 종료를 반영한다. |
| Watch 지연·중복 | 확인 전 큐 유지·재시도, 동일 UUID 중복 저장 방지. 실제 전달은 페어링 기기에서 확인한다. |
| PDF 선택·기록 변경 | 기존 문서와 동의를 무효화하고 재생성·확인하게 한다. 오래된 문서로 공유하지 못한다. |
| 공유 취소·재시도 | 자동 전송하지 않는다. 원본 기록은 유지하고 공유 시트 개방 후 동의를 초기화한다. |

## 10 피드백 추적과 검증 상태

| 피드백 | 연결 요구사항 | 이번 개정 |
|---|---|---|
| P03 근거·운동 질문 | FR-03·05·06·07 | 운동 미기록 구분, 표현 변형, 비교 기준·계산 근거와 한계, T2·T3 재시험. |
| P05 일정 미반영 | FR-08·09·10 | 종료 시각·자정·준비 30분·부족 수면·대안 기상, T4 재시험. |
| P05 공유 통제 | FR-11·12, NFR-04 | 날짜·필드 선택 → 로컬 미리보기 → 최종 동의 → 사용자 대상 선택, T5 재시험. |

2026-11-08: 도메인 자동 검사 105개 통과. iPhone·임베드 Watch 기기용 서명 없는 빌드와 시뮬레이터용 빌드 성공. iPhone 시뮬레이터에서 운동 입력·질문 인식·자정 일정·선택 PDF·동의 취소를 확인했다. 합성 30건의 실제 UIKit PDF 생성기는 최소 선택 1페이지, 운동만 2페이지, 전체 선택 3페이지로 누락 없이 출력했다.

이는 개발 검증 결과다. P03·P05 개선 후 고객 재시험, 실제 HealthKit·Watch 운동 전달·기기 공유 결과는 아직 확인하지 않았다. 고객 결과를 추정해 채우지 않는다.

## 11 LLM API 연동 요구사항 설계안

이 절은 API 기반 LLM을 사용한다고 가정한 목표 요구사항이다. v1.5는 문서 개정 버전이며 앱에 API가 연결됐다는 뜻이 아니다. 현재 영상의 질문·답변은 로컬 규칙으로 동작한다. 공급자·모델·서비스 URL·배포 방식은 미정이며 실제 호출·지연·비용·정확도는 검증 전이다.

| ID | API 연동안의 요구사항 | 인수 기준과 상태 |
|---|---|---|
| FR-13 | 질문과 선택 기간·항목, 로컬 계산 근거를 LLM에 전달해 기록 설명을 생성한다. | 현재 로컬 결과와 LLM 생성 설명을 구분한다. 응답의 참조 기록 ID와 수치를 검사하며 근거가 없으면 안내한다. 설계·미검증. |
| FR-14 | 선택 기록으로 상담용 요약 문장 초안을 생성한다. | 생성 설명임을 표시하고 사용자 검토 후에만 PDF에 포함한다. 수치·날짜·출처는 로컬 원자료와 대조한다. 설계·미검증. |
| FR-15 | API 전송 전 데이터·질문과 외부 처리 범위를 보여주고 명시적 동의를 받는다. | 미동의 시 요청하지 않으며 로컬 질문·PDF 경로를 유지한다. LLM 전송 동의와 최종 PDF 공유 동의는 별도다. 설계·미검증. |
| FR-16 | 로딩·취소·실패·응답 유효성을 처리한다. | 취소·오프라인·시간 초과·인증/한도 오류를 구분한다. 실패를 LLM 성공으로 표시하지 않고 재시도와 로컬 결과를 제공한다. 설계·미검증. |
| NFR-08 | 중계 서버에 공급자 키를 보관하고 선택 최소 자료만 HTTPS로 전달한다. | 앱 번들에 공급자 키를 넣지 않는다. 원자료 로그·보관 정책과 공급자 조건은 구현·배포 전에 확정한다. 설계·미검증. |

T6 API 질문 검증: 선택 자료·동의, 정상 응답의 근거 ID·수치·생성 표시, 자료 부족·취소·시간 초과·키/한도 오류·로컬 복귀를 확인한다. T7 API 요약 검증: 선택값만 전송하고 제외값이 응답·PDF에 섞이지 않는지, 사용자 검토와 최종 공유 동의를 확인한다. 두 과업의 측정 결과는 아직 없다.

기존 105개 도메인 검사는 로컬 계산·저장·선택 PDF 등을 대상으로 한 결과이며 LLM API 성공률에 포함하지 않는다. 질문 텍스트에도 민감정보가 들어갈 수 있으므로 전송 미리보기에 포함하고, 미선택 기록과 직접 식별자는 보내지 않는 설계로 한다.
