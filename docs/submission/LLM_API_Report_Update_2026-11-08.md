# LLM API 연동 가정의 보고서 반영

2026-11-08. 사용자의 지시에 따라 실제 앱 연동 구현에 앞서 API를 사용한다고 가정한 설계안을 보고서에 반영했다. 문서 버전은 v1.5, UI/UX 버전 사본은 v7이다. 실제 LLM API 연결·응답·배포·성능 검증이 완료됐다는 뜻은 아니다.

| 자료 | 반영 내용 |
|---|---|
| 01 SSRD | LLM API를 추가 설계 범위로 정의. FR-13 질문 설명, FR-14 상담 요약 초안, FR-15 전송 미리보기·별도 동의, FR-16 취소·실패·복귀, NFR-08 중계 서버·키 보호와 T6·T7 검증 계획. |
| 02 UI/UX | 질문 화면의 API 흐름·동의·생성 표시·오류를 설계 예시로 표현. 현재 구현과 API안을 구분하고 최종 PDF 공유 동의와 외부 처리 동의를 분리. |
| 03 SSAD | 13~14절에 중계 서버·외부 LLM·선택 맥락·응답 검사 구조, 자료 사전·오류·검증안을 추가. 기존 구현 모듈과 제안 모듈을 구분. |
| 05 4차 초안 | 9절에 API 가정·사용자 흐름·T6·T7 미측정 평가안을 추가. 6명 수치·발언과 기존 완료율의 해석 범위를 유지. |

질문·선택 기간·필드·로컬 계산 사실을 확인하고 외부 처리에 동의하면 중계 서버를 통해 LLM API를 호출하는 안이다. 공급자 키는 앱에 넣지 않고 서버에서 관리한다. 공급자·모델·서비스 URL·인증·비용·보관 조건은 미정이다. 수면 수치·취침 계산은 로컬 근거를 유지하고 LLM이 설명·요약 초안을 생성하도록 구분한다.

API 정상·오류 응답, 최소 선택 자료, 미동의 차단, 늦은 응답 무효화, 생성 표시·근거와 수치 확인, 사용자 검토와 최종 공유를 새로 검증해야 한다. 기존 105개 검사·6명 평가·영상 장면을 API 검증 결과로 바꾸지 않았다. 기존 영상의 질문·답변은 로컬 규칙 방식이다. 고객 인용문은 그대로 보존했다.

앱 Swift 코드와 Xcode 설정, 실제 고객 원자료, 과거 v4~v6 덱과 3차 보고서는 이번 작업에서 변경하지 않았다. 문서에 API가 있다고 가정한 역할과 실제 구현 완료 상태가 혼재하지 않도록 표·본문에 설계안·미검증 상태를 표시한다.

재생성은 scripts/sync_submission_documents.py, scripts/sync_submission_deck.sh, scripts/render_submission_documents.sh를 사용한다. 고객 보고서 4차는 기존 자료를 보존한 편집 원본이다. 영상 재촬영·YouTube 업로드·실제 API 연결은 이번 문서 작업 범위에 포함하지 않는다.

문서 확인: SSRD 6쪽, UI/UX 13슬라이드, SSAD 14쪽, 고객 보고서 9쪽을 렌더링했다. 변경된 페이지와 슬라이드를 직접 확인하고 이전과 같은 페이지는 이미지 비교로 확인했다. Office 압축 무결성·덱 재가져오기·폰트/크기/네이티브 표 검사·Markdown 링크·원문 수치와 발언 보존을 확인했다. 앱 코드 변경이 없어 기존 앱 테스트를 다시 실행한 것으로 기록하지 않는다.
