# 잠만보 고객 사용성 테스트 패킷

> **빈 양식입니다.** 아직 참여자 모집이나 테스트는 진행하지 않았으며, 이 문서에는 실제 참여자 결과가 없습니다.

## 1. 테스트 목적

수면 기록에 관심 있는 사용자가 잠만보의 수면 요약, iPhone 체크인, 기록 기반 질문, 수면 목표와 상담용 요약을 이해하고 사용할 수 있는지 확인합니다. 첫 회차는 iPhone 중심으로 진행하고, Watch 체크인은 페어링과 전달이 확인된 기기에서만 추가합니다. 이 테스트는 사용성·이해도·체감 유용성을 살피며 수면의학적 진단이나 수면 개선 효과를 평가하지 않습니다.

예상 진행 시간은 15~20분입니다. 참여 인원과 모집 기간은 팀이 정하고 과제의 공식 기준과 혼동하지 않도록 별도로 기록합니다.

## 2. 진행 전 확인

- [ ] iPhone 앱을 설치해 실행했다. Watch 과업을 포함할 때만 Watch 앱 설치와 페어링도 확인한다.
- [ ] 테스트 기기에서 HealthKit 화면의 데이터 출처가 `샘플`인지 확인한다. 개인 HealthKit 기록을 테스트 기기에 불러오지 않는다.
- [ ] 선택 과업 T2b를 수행한다면 Watch 체크인 전달을 사전에 확인한다. 확인되지 않으면 iPhone 과업만 진행하고 T2b는 실행 불가로 적는다.
- [ ] 테스트 중 화면 녹화, 사진 촬영, PDF 공유는 기본적으로 하지 않는다.
- [ ] 실제 기록이 화면에 나타나면 즉시 멈춘다. 샘플 경로를 확보할 수 없으면 해당 과업은 실행하지 않는다.
- [ ] 참여자에게 테스트 목적, 기록 항목, 중단 방법을 설명한다.
- [ ] 기록지는 참여자 코드로만 작성하고, 이름·이메일·전화번호·생년월일을 적지 않는다.

Watch가 연결되지 않거나 실제 설치가 되지 않으면 실패로 단정하지 말고 해당 과업을 `실행 불가`로 표시합니다. 전달 결과를 추측해 쓰지 않습니다. iPhone 실행 확인은 Watch 전달 성공을 의미하지 않습니다.

## 3. 참여 안내 및 동의 문구

진행자는 아래 내용을 읽고 참여자의 동의를 받습니다.

> 잠만보의 화면과 사용 흐름을 확인하는 수업 프로젝트 테스트입니다. 의료 진단이나 치료 효과를 평가하지 않습니다. 참여는 자발적이며 원하면 언제든 멈출 수 있습니다. 기본 테스트는 개인 건강 기록이 없는 테스트 기기의 샘플 수면 기록을 사용합니다. 개인 iPhone의 HealthKit 권한을 새로 허용하도록 요청하지 않습니다. 참여자가 개인 기기에서 직접 시험하기를 원하면 실제 수면 데이터가 화면에 표시될 수 있음을 먼저 설명하고 별도 동의를 받습니다. 실제 수면 수치·건강 데이터·계정 정보는 연구 기록지에 적거나 촬영하지 않으며, 수치가 나타나면 즉시 화면을 닫거나 테스트를 멈춥니다. 기록할 내용은 참여자 코드, 과업 완료 여부와 시간, 도움이나 오류 여부, 참여자가 말한 사용 의견입니다. 결과는 개인을 알아볼 수 없도록 요약합니다. 이 설명을 이해했고 자발적으로 참여하는 데 동의하십니까?

| 항목 | 기록 |
|---|---|
| 참여자 코드 | `P__` |
| 테스트 일자 |  |
| 안내 확인 | 예 / 아니요 |
| 참여 동의 | 예 / 아니요 |
| 인용문 익명 사용 동의 (선택) | 예 / 아니요 |

동의하지 않으면 테스트를 진행하지 않습니다. 동의 기록에도 실명이나 연락처를 적지 않습니다. 참여자가 중단을 원하면 즉시 멈추고 해당 코드의 메모를 결과 분석에서 제외합니다.

## 5. 진행 방법

1. 동의를 확인하고 참여자 코드를 부여합니다.
2. 기능을 먼저 설명하지 않고 과업을 한 번에 하나씩 읽어 줍니다.
3. 참여자가 직접 사용하는 동안 완료 시간, 도움 요청, 오류·재시도만 기록합니다. 실제 수면 수치를 받아 적지 않습니다.
4. 과업 후 간단한 평점과 개방형 질문을 진행합니다.
5. 관찰 메모를 익명화하고, 반복 의견과 해결할 문제를 정리합니다.

완료율의 분모는 해당 과업을 실제 실행할 수 있었던 참여자 수입니다. 실행 불가는 실패와 따로 집계합니다. Watch 선택 과업은 iPhone 핵심 과업의 완료율에 섞지 않습니다.

과업별 시간은 진행자가 시작 문장을 읽은 시점부터 참여자가 완료했다고 말할 때까지 잽니다. 과업 도중 기능을 설명하거나 힌트를 제공하면 도움 횟수에 기록합니다.

## 6. 사용성 과업

| ID | 참여자에게 읽어 줄 과업 | 완료로 볼 기준 |
|---|---|---|
| T1 오늘 수면 확인 | “오늘 화면에서 수면 요약을 찾아보고, 데이터가 어디에서 왔는지 알려주세요.” | 수면 요약과 `샘플` 또는 `건강 앱` 출처를 찾고 설명한다. |
| T2a iPhone 체크인 | “iPhone에서 기분과 스트레스, 오후 카페인 여부를 선택해 저장하고 목록에서 찾아주세요.” | 전체 기록에서 값과 iPhone 출처를 찾고 상세에서 수정한다. 재실행 후 유지도 확인한다. |
| T2b Watch 전달 선택 과업 | “Watch에서 체크인을 저장하고 iPhone에서 도착 여부를 확인해 주세요.” | 실제 수신값·Apple Watch 출처와 Watch 저장 확인을 본다. 오프라인 후 재연결과 중복도 확인한다. 연결이 안 되면 실행 불가로 기록한다. |
| T3 기록에 질문 | “최근 평균 수면을 확인하고, 답변의 근거가 된 기간과 출처를 찾아주세요.” | 답변과 근거 기간·출처를 찾는다. 기록 부족 안내가 나오면 그 안내를 이해하는지도 기록한다. 샘플 수면에서는 개인 체크인 비교가 제한되는지 확인한다. |
| T4 수면 목표와 일정 | “목표 수면을 8시간, 기상 목표를 오전 7시로 설정하고 취침 목표를 확인해 주세요. 일정 하나를 직접 입력해 목록에서 찾아주세요.” | 계산된 취침 목표와 직접 입력 일정이 보이는 위치를 찾는다. 캘린더 자동 연동으로 오해하는지도 확인한다. |
| T5 상담용 요약 | “최근 기록 요약을 살펴보고 PDF를 만들어 주세요. 공유 대상을 선택하지 말고 내용과 데이터 출처를 확인한 뒤 멈춰 주세요.” | 내부 미리보기에서 1페이지·출처를 확인한다. 체크인 변경 후 새 PDF에 반영되는지도 보고 공유 없이 종료한다. |

## 10. 보고서 구성과 Go/Stop/Pivot 판단

제출용 고객 피드백 보고서는 아래 순서로 작성합니다.

1. 테스트 목적과 프로토타입 범위
2. 참여자 수와 익명 특성, 동의 절차
3. 설문·인터뷰 질문과 사용 과업
4. 과업 완료·시간·도움·오류 결과
5. 반복 피드백 주제와 이를 뒷받침하는 익명 근거
6. 바꿀 점과 우선순위
7. Go/Stop/Pivot 결정, 결정 근거, 다음 검증 계획

아래 기준은 **팀이 참여자 모집 전에 합의할 제안값**이며 수업의 공식 기준이나 임상 기준이 아닙니다. 표본이 작으므로 결과는 초기 사용성 판단으로만 해석합니다.

- **Go:** 중대한 개인정보·안전 문제가 없고, 핵심 과업(T2a·T3·T5)의 80% 이상을 도움 없이 완료했으며, 이해도·재사용 의향의 중앙값이 4점 이상이면 현재 방향으로 다음 사용성 개선을 진행합니다.
- **Pivot:** 중대한 안전 문제는 없지만 핵심 과업 완료율이 80% 미만이거나 같은 사용성 장애가 두 명 이상에게 반복되면 흐름·문구·기기 역할을 바꾸고 다시 확인합니다.
- **Stop:** 실제 기록이 동의 없이 외부로 공유되거나, 개인정보 노출 또는 진단·치료 오해를 유발하는 중대한 문제가 발견되면 해당 기능의 테스트·공개 시연을 중단하고 문제를 해결한 뒤 재개합니다.

Go는 수면 개선 효과를 입증하지 않습니다. 기록 수치의 원인이나 임상적 효과에 관한 결론은 이 테스트에서 내리지 않습니다.

## 11. 데이터 보관 및 정리

- 이름·연락처·생년월일·원본 건강 기록·HealthKit 화면 사진·식별 가능한 영상은 수집하지 않습니다.
- 기본은 개인 기록이 없는 전용 테스트 기기의 샘플 경로입니다. 참여자가 개인 HealthKit 데이터를 직접 보며 시험하기를 원할 때는 별도 동의를 확인하고, 진행자는 수치를 기록하거나 촬영·PDF 내보내기를 하지 않습니다. 개인 기록이 화면에 나타나면 테스트를 일시 중단하고 참여자에게 계속할지 확인합니다. 샘플 출처를 확보할 수 없는 기기에서는 T1과 T5를 실행하지 않습니다.
- 관찰 메모는 코드만 사용하고 `docs/user-test/raw/`에 둘 경우 Git에 올리지 않습니다. 최종 보고서에는 익명 집계와 동의된 비식별 인용만 반영합니다.
- 테스트 종료 시 참여자에게 앱에서 생성한 요약 PDF를 저장하거나 공유하지 않았는지 확인하고, 테스트 파일을 외부로 전송하지 않습니다.
- 보관 기간과 삭제 책임자는 테스트 전에 팀이 정하고 기록합니다. 해당 항목은 실제 학교·수업의 지침을 확인한 뒤 확정합니다.

GitHub 소스와 화면 녹화를 AI 에이전트가 검토한 결과는 보조 코드·사용성 검토로 별도 기록합니다. 실제 사용하지 않은 AI의 의견을 고객 인터뷰, 참여자 발언, 과업 성공률에 포함하지 않습니다. 검토 요청 방법은 [AI 리뷰 안내](../qa/AI_Review_Guide.md)를 참고합니다.
